## ASR Experiments

> **Deployable-checkpoint audit (updated 2026-05).** Authenticated Hugging Face sweeps (`huggingface_hub.list_repo_files`) against `JosueG/adja-asr-results`:
> - `E4/` — **absent.** Training logs tied to legacy run **E4** once showed **24.90% / 73.09% WER,CER**, but checkpoints were never mirrored as standalone `from_pretrained`-ready repos and the umbrella-folder copy is retired.
> - `C2/` — **absent.** The headline **27.02% / 74.15% WER,CER** *direct Whisper-small* numbers likewise survive only offline; `C2_redo/` still holds weights emitting **≈106% CER** (EOS-mask hallucination bug), leaving **`JosueG/whisper-ewe-adja-e4v4`** as the public Whisper baseline.
> - `C4v2/best_model/` — has `config.json` + `model.safetensors` but **no tokenizer / processor files**. Vocab is reconstructable from [scripts/hf_jobs/ctc_finetune.py](../scripts/hf_jobs/ctc_finetune.py:53-64) (deterministic NFC chars from `JosueG/adja-tts-orpheus`).
> - `E4v4/best_model/`, `E4_redo/best_model/`, `C2_redo/best_model/` — full Whisper artifacts, but redo runs are broken (CER >80% from EOS-mask hallucination); E4v4 is the only viable surviving Whisper-Ewe→Adja (CER 37.18%, overfit).
>
> **Net effect for the reverse-WER TTS eval (2026-04-28):** the two genuinely deployable Adja ASRs are **C4v2** (after rebuilding the tokenizer) and **E4v4** (deploys as-is). E4-original is treated as a published metric only; we do not claim a 24.90%-grade ASR exists in serving form. See [<LOCAL_PATH> for the eval plan.
>
> **Reproducible qualitative decodes (added 2026-05-03).** The Chapter 4 sample-decode table is now regenerable from the deployed endpoints with a deterministic seed=42 test slice via [scripts/qualitative/regen_asr_decodes.py](../scripts/qualitative/regen_asr_decodes.py). ## TTS Experiments

### Data-choice note (2026-04-22): WaxalNLP `ewe_tts` vs `ewe_asr`

All Stage 1 Ewe-pretraining jobs in this wave use `google/WaxalNLP` config **`ewe_tts`** (1,215 train + 152 val + 152 test = 1,519 clips), **not** the much larger `ewe_asr` config (15,054 train + 1,916 val + 1,891 test + 183,920 unlabeled). WaxalNLP separates the two because TTS needs cleaner, more prosodically consistent audio (fewer speakers, studio quality), while ASR benefits from diversity. The `ewe_asr` variant is logged as a planned ablation (does 12× more data help or hurt Stage 1 TTS quality?) — see `docs/gbe-cascade-tts-settings-2026-04-22.md` §2.2 and §7 for the paper-facing rationale.
